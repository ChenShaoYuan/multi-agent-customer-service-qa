# 预检规则清单与触发条件

## 1. 预检边界

预检由确定性 Python 逻辑实现，只输出可重复计算的事实。需要理解语义、行为对象、权限或免责条件的判断交给 Agent。

例如：

- 预检可以输出“客服消息 m4 命中词语‘不归我们管’”。
- 预检不能直接输出“客服严重推诿并触犯红线”。

## 2. 规则清单

| 编号 | 检查项 | 触发条件 | 输出字段 | 是否直接扣分 |
|---|---|---|---|---|
| PF-01 | 输入完整性 | 工单号、标签或对话为空 | `input_errors` | 否，决定拒绝或人工复核 |
| PF-02 | 角色合法性 | 角色不属于 `end-user/agent/system` | `role_errors` | 否 |
| PF-03 | 旧样例适配 | 只有 `comments` 且符合当前样例约定 | `role_source=inferred` 和推断消息 | 否 |
| PF-04 | 时间合法性 | 时间戳缺失、无效或消息时间逆序 | `timing_available`、`timing_errors` | 否 |
| PF-05 | 对话统计 | 存在有效消息 | 各角色消息数、有效轮次 | 否 |
| PF-06 | 欢迎语 | 第一条人工客服消息未命中欢迎模式 | 布尔值和证据消息 | 否，供流程 Agent 使用 |
| PF-07 | 结束语 | 最后一条客服消息未命中礼貌结束模式 | 布尔值和证据消息 | 否，供流程 Agent 使用 |
| PF-08 | 接入时效 | 连接人工提示到首次人工回复大于90秒 | 秒数和相关消息 | 仅时间可用时供评分 |
| PF-09 | 回复时效 | 用户消息到下一客服回复大于300秒 | 超时列表 | 仅时间可用时供评分 |
| PF-10 | 红线词线索 | 客服消息命中风险词库 | 词语、消息编号、上下文窗口 | 否，交主控判断 |
| PF-11 | 敏感信息线索 | 命中手机号、身份证、Token等模式 | 信息类型和脱敏证据 | 否，交主控判断 |
| PF-12 | 标签合法性 | 父标签不在22类目录或子标签为空 | `tag_warnings` | 否 |
| PF-13 | 重复回复 | 客服连续重复相同或高度相似短句 | 消息编号列表 | 否，供主控参考 |
| PF-14 | 转接事实 | 出现系统或客服转接事件 | 转接次数、话术和消息编号 | 否，供沟通 Agent 使用 |

## 3. 数据不足策略

| 缺失数据 | 处理方式 |
|---|---|
| 对话为空 | 输入无效，停止模型调用 |
| 角色缺失 | 当前100条样例允许适配器推断；正式输入转人工复核 |
| 时间戳缺失 | 所有时效项标记 `not_evaluable`，不扣分 |
| 父标签未知 | 不猜测专业规则，转人工复核 |
| 子标签为空 | 记录告警；其他信息充分时可继续红线审核 |
| 系统转接事件缺失 | 转接规范仅根据可见消息判断，并标记证据限制 |

## 4. 建议预检输出

```json
{
  "input_valid": true,
  "input_errors": [],
  "role_source": "provided",
  "timing_available": true,
  "conversation_stats": {
    "message_count": 8,
    "user_count": 4,
    "agent_count": 4,
    "system_count": 0,
    "turn_count": 4
  },
  "greeting": {"present": true, "message_id": "m2"},
  "closing": {"present": true, "message_id": "m8"},
  "response_time_violations": [],
  "redline_keyword_hits": [],
  "sensitive_data_hits": [],
  "tag_warnings": [],
  "transfer_events": []
}
```

## 5. 第二周实现要求

1. 每条规则写成独立、可单测的函数。
2. 正则和词表放入配置，不散落在节点代码中。
3. 输出消息编号，便于 Agent 引用证据。
4. 敏感信息证据必须先脱敏再写日志。
5. `redline_keyword_hits` 与 `redline_triggered` 必须是不同字段。
